\paragraph{The problem.}
RL fine-tuning of LLMs has moved from short chat responses to long-context
regimes: long chain-of-thought for reasoning
\citep{guo2025deepseekr1,shao2024grpo} and long inputs for retrieval,
multi-document QA. Both directions grow the KV
cache linearly with sequence length, and in the policy-gradient step that
cache must be held (or recomputed) for every token that receives a gradient.
On commodity single-GPU hardware this is the binding constraint: dense GRPO on
Qwen2.5-7B exhausts a 48\,GB L40S at 24k tokens (\cref{tab:memory_frontier}).

\paragraph{What existing work does.}
The dominant answer is to make the \emph{rollout} cheaper while leaving the
\emph{policy} dense. Sparrow \citep{sadhukhan2026sparrow} generates with
block-sparse attention and trains a dense policy on those samples, and shows
that stability hinges on keeping the lower tail of the per-token
actor--policy mismatch above a threshold. Related work on off-policy
correction treats the same mismatch with truncated importance sampling
\citep{espeholt2018impala}. All of these accept a distribution gap between
the sampler and the model being trained and then manage it. The
gradient pass itself stays dense, so its memory still grows with the full
rollout length.

\paragraph{Our approach.}
We make the whole step sparse. \method{} runs chunked prefill, generation and
a bounded-memory chunked backward pass through the same actively evicting KV
cache (H2O-style heavy-hitter eviction \citep{zhang2023h2o} with 8-bit KV
quantisation). The log-probabilities used for the GRPO/RLOO ratio are the ones
produced during sampling, so there is no actor--policy mismatch to correct.
The cost is that the policy itself is now a sparse-attention model at
training time and its accuracy is bounded by what survives eviction.

\paragraph{Contributions.}
\begin{enumerate}
  \item \textbf{A memory frontier.} Bounded evicting cache keeps peak memory
    flat (35.7\,GB) from 24k to 65k context on a 7B model where dense GRPO
    fails at 24k and even a full-coverage sparse cache fails at 32k
    (\cref{sec:memory}).
  \item \textbf{Flat decode cost.} Dense rollout throughput halves from 4k
    to 8k context and fails at 16k for a batch of 8; the bounded cache
    holds 32 tokens/s and 29\,GB from 8k to 32k, matching dense where dense
    fits (\cref{sec:decode}).
  \item \textbf{Parity where dense fits.} On the RLVR math suite (AIME,
    AMC, MATH500), GRPO/RLOO through the evicting cache matches
    dense-attention training within noise on every paired comparison, two
    seeds (\cref{sec:parity}).
